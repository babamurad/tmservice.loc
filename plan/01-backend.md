### Этап 2A. Верификация телефона (OTP) — до публичного запуска

> **Открытый вопрос — SMS-шлюз для Туркменистана.** Доставка SMS на `+993`
> через международные шлюзы (Twilio и т.п.) может быть нестабильной —
> телеком в стране ограничен. Спайк по реальному шлюзу **осознанно не
> проводился** — сделана только `LogSmsGateway` (код в лог), чтобы не
> блокировать разработку и тесты. **Реальная доставка SMS на `+993` не
> работает, пока это не заменят на настоящего провайдера** — см. Шаг 2A.5.

- [x] Шаг 2A.1: Таблица `phone_verifications` — `id`, `phone` (index), `code` (6 цифр), `expires_at`, `attempts` (default 0), timestamps.
- [x] Шаг 2A.2: `POST /api/auth/send-otp` (`OtpController@send`) — генерирует 6-значный код (TTL 5 мин), пишет/обновляет запись в `phone_verifications`, отправляет через `SmsGateway`.
- [x] Шаг 2A.3: `POST /api/auth/verify-otp` (`OtpController@verify`) — сверяет код (`hash_equals`) и срок, лимит попыток (5), при успехе удаляет запись и вызывает `User::markPhoneAsVerified()`.

- [~] Шаг 2A.5: Интерфейс `App\Contracts\SmsGateway` — сделано, реализация одна:
  - [x] `App\Services\Sms\LogSmsGateway` — пишет код в лог (`Log::info`), реальные SMS не уходят. Забинжена в `AppServiceProvider::register()` как единственная реализация.

### Этап 2B. Rate limiting — до публичного запуска

**Проблема**: `GET /api/masters/{id}` отдаёт телефон публично (by design),
но без лимита базу легко спарсить. `login`/`send-otp` без лимитов открыты
для брутфорса и SMS-флуда (SMS — это ещё и деньги).

- [x] Шаг 2B.1: Именованные лимитеры — сделано в `app/Providers/AppServiceProvider.php@boot()` (не в `bootstrap/app.php` — там для этого нет подходящего хука в Laravel 13, `RateLimiter::for` регистрируется в провайдере):
  ```php
  RateLimiter::for('public-read', fn (Request $r) => Limit::perMinute(60)->by($r->ip()));
  RateLimiter::for('auth',        fn (Request $r) => Limit::perMinute(5)->by($r->ip()));
  RateLimiter::for('otp',         fn (Request $r) => Limit::perMinutes(60, 5)->by($r->input('phone')));
  ```
- [x] Шаг 2B.2: `throttle:public-read` на `GET /api/masters`, `GET /api/masters/{id}` (`routes/api.php`).
- [x] Шаг 2B.3: `throttle:auth` на `login`/`register`, `throttle:otp` на `send-otp`/`verify-otp` — подключено вместе с Этапом 2A.

Покрыто тестами: `tests/Feature/RateLimitTest.php` — 6-я подряд неудачная
попытка логина за минуту → `429` с `Retry-After`; 61-й запрос `GET /api/masters`
за минуту → `429`. Полный набор тестов (`php artisan test`) — зелёный.

**Критерии приёмки**: превышение лимита → `429` с `Retry-After`. Массовый перебор `masters/{id}` упирается в лимит.

### Этап 4A. QR через Universal Links / App Links (замена кастомной схемы)

**Проблема**: `appscheme://master/{id}` срабатывает только если приложение
уже установлено. Клиент сканирует визитку без приложения — ссылка молча
ничего не делает. Для QR, чей смысл — привлекать новых клиентов, это
провал сценария.

- [ ] Шаг 4A.1: QR кодирует `https://{домен}/m/{id}` вместо кастомной схемы.
- [ ] Шаг 4A.2: Веб-страница `/m/{id}` (единственное исключение из
  «только JSON» — можно Blade): если приложение установлено → ОС сама
  откроет его; если нет → карточка мастера + кнопки «Открыть в приложении /
  App Store / Google Play».
- [ ] Шаг 4A.3: Файлы ассоциации доменов:
  - iOS: `https://{домен}/.well-known/apple-app-site-association` (без расширения, `Content-Type: application/json`).
  - Android: `https://{домен}/.well-known/assetlinks.json`.

**Критерии приёмки**: скан QR с приложением → открывается `MasterDetailScreen` нужного мастера. Без приложения → веб-страница с переходом в стор.
